# 0046-FEAT — Implementation plan and acceptance gates

**All four steps: OPEN / NOT STARTED.** The accepted 0045 closure is an explicit prerequisite. Implement this as **one coherent inventory migration and one consolidated verification**, not as a series of artificial mini-deployments.

## Step 1 — Freeze the post-0045 source, old inventory and installed baselines (OPEN)

**Prerequisite:** 0045 formally CLOSED, with its Playbooks and Diaries publication receipts accepted. Verify the separate authoritative Windows Diaries and `mango` Playbooks Git states (branch, full SHA, clean/staged/untracked state, remote, submodule pins for Diaries). Use the actual then-current Playbooks revision and the current production inventory, **not** planning-time Git SHAs or the 9 November source bundle.

- On **`mango`**, record active Ansible version, collections/plugins, actual `ansible.cfg` source and relevant effective settings (`ansible --version`; sanitised `ansible-config dump --only-changed`), inventory sources and order, groups/hosts and any `ANSIBLE_CONFIG`/`ANSIBLE_INVENTORY` environment overrides. Audit current launcher/workflow `cd` assumptions, `-i`/`--inventory` use, cron/CI/operator commands and playbook-relative variable directories.
- Inventory and security inventory: enumerate `/etc/ansible/hosts`, `group_vars/`, `host_vars/`, nested group/host directories, dynamic inventory/plugins, possible file/directory/symlink dependencies, existing Vault files including embedded `!vault`, permissions, ownership and reference paths. Classify **every file and variable** as non-secret, protected secret or unknown; an unknown must be resolved before copying to Git.
- Enumerate **every managed host**, all playbook entry points, tag/limit combinations used operationally, and their expected managed installation footprints. Capture effective-variable maps and source/precedence information as **diagnostic input**, including protected-value comparisons performed safely in memory; do not make identical maps an acceptance prerequisite. Record the then-current `btrfs_native_endpoint_role` mappings and central Btrfs schedule for `mars` and `backup`. Never export decrypted output.
- Freeze the set of then-current Playbooks role/template contents and task/entry-point inputs; 0046 shall not modify this installation-producing source while claiming inventory-only equivalence.
- Build a **per-host installation baseline for the entire managed estate**, not merely `mars` and `backup`. Where applicable, reuse accepted **0045** collectors for Btrfs endpoints. Record managed paths, content hashes (secret-bearing data compared privately), owner/group/mode, ACL/sudoers, units/cron/mounts/timers, packages/services, active opt-ins and expected-absent paths. Record backup health separately; exclude legitimately mutable application/backup datasets and timer counters from byte-for-byte comparison. An unmeasured host is an **open acceptance gap**.

**Evidence:** `evidence/Step 1/` source and inventory manifests, a complete per-host/per-playbook coverage matrix, private-data-safe command receipts, 0045 acceptance reference and installation manifest schemas (including the `mars`/`backup` readbacks). Keep secret values out of both Git repos and feature evidence.

**Gate:** baseline and classification accepted; secret-loading and duplicate-source risks mapped. If a current source/inventory difference from planning assumptions matters, amend the 0046 plan before implementation.

## Step 3 — One consolidated effective-inventory and installed-state acceptance (OPEN)

**Freeze the Playbooks role/installation SHA across both sides of the comparison.** Use the same live hosts, Ansible version, packages/plugins and intended flags. A source-code or inventory-value change during verification requires a fresh baseline or an explicitly accepted correction; do not compare different code revisions and call the result an inventory migration.

1. **Complete host/playbook matrix:** enumerate all hosts selected by each then-current operational playbook under **both inventory locations**, including relevant tags and limit patterns. Host omission, addition or mis-targeting that changes what would be installed is a failure. Explicit `-i` is permitted within isolated comparisons; normal post-cutover commands should use repository `ansible.cfg`.
2. **Diagnostic variable comparison:** compare effective values, undefined states, precedence and Vault loading **for every host**, without logging secrets. Differences are **investigations**, not automatic failures: accept them only if their lack of effect on install results, activation and security is demonstrable. Missing credentials or weakened security remain failures regardless of installation hashes.
3. **All-host installation-output equality:** for **every managed host and applicable playbook**, compare exactly what the original inventory would install with what the new inventory would install, holding the installation-producing Playbooks SHA and other inputs constant. Use repeatable source/rendered-output comparisons, a full per-host installation footprint, and controlled before/after installed-state readbacks. Include packages, static/templates, filesystem ownership/mode, ACLs, users, services/timers, schedules, mounts, privileges and security policy. Use safe controlled applications on hosts as necessary; do not rely on representative-host testing or syntax/`--check` output alone. If safe equivalence cannot be demonstrated for a host, mark it **OPEN** rather than declare estate-wide success.
4. **Regression, runtime and security verification:** run the maintained backup/Btrfs regressions and appropriate playbook syntax/host/tag checks; check normal Vault discovery, scripts and scheduled launchers for the wider estate. On `mars`/`backup`, verify replication, pruning, agreed-parent pins and qgroups remain safe without manually running destructive operations. Account only for explicitly classified volatile runtime data, not for managed installed differences.
5. **Cutover and review:** switch normal Playbooks invocations to repository inventory only after the whole-estate comparison is viable. Apply the frozen Playbooks with normal Vault handling where needed to establish installed equality, compare the same schema and collectors before/after, review any `changed` results, and verify no host was skipped. Restore old inventory selection if a target discrepancy or unsafe operation is detected.

**Evidence:** `evidence/Step 3/` complete non-secret equivalence report, protected-data equality status, exact installed manifest diff/zero-mismatch receipt, Ansible logs, pre/post status, controlled activation and rollback readiness, consolidated regressions.

**Gate:** **Every managed host and applicable playbook produces the identical installed result under old and new inventory locations**, with a complete accepted coverage matrix and no security/secret-loading regressions. Equal variable maps or precedence are **not** required. Any host not verified, unexplained installed-result delta, dangerous action or secret exposure keeps the feature OPEN; restore the old inventory selection and retest only affected cases.
