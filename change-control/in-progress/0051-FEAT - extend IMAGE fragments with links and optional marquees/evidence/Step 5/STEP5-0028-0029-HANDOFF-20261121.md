## Implemented 0051 contract

```text
MARQUEE => no catalogue Image, no IMAGE link; optional/legacy same-page Marquee
IMAGE   => optional catalogue Image, optional validated per-Fragment HTTP(S) link,
           zero or one same-Page source Marquee
```

- `Fragment.imageLinkUrl` persists in nullable PostgreSQL `fragment.image_link_url` (`VARCHAR(4096)`). Link belongs to **Fragment occurrence**, not the shared catalogue Image.
- For an ordinary Fragment update: omitted `imageId`/link fields must preserve existing values; an explicit relationship set/clear uses the designated mutation RPC. Never infer deletion from omission.
- A Marquee is associated with at most one Fragment; its Page must agree with that Fragment's authoritative Page. Preserve approved Marquee ID/version/geometry on conversion unless independently authorised to remove it. Do not emit a tombstone for a preserved Marquee.
- Catalogue Image metadata and file bytes are reusable; deleting an IMAGE Fragment or its Marquee never implicitly deletes the shared Image.
- The Day Reader header displays `Image ID: N` after Position and the catalogued IMAGE beneath the header; legacy embedded images remain legacy MARQUEE HTML until 0028 separately migrates them.
