# 0035 — Push-replication retention contract (2026-10-12)

**Status:** design approved, integration acceptance OPEN. Aligns with `0034/evidence/Step 10/PUSH-ARCHITECTURE-DECISION-20261012.md`.

`mars` will initiate outbound Btrfs push to `backup`, whereas the existing source-side 0035 timestamped snapshot manager still exclusively owns local snapshot creation/pruning. `backup` exclusively verifies accepted receives and its own retention. Preserve root-owned `/media/usb/@snapshots/.replication-protection.json` (`schema:1`, protected mapping snapshot timestamp → source UUID) and its lock as deployed. A source snapshot accepted as common parent and an in-progress child candidate remain pinned. The source manager must validate pin UUID and reject missing, malformed, unsafe or inaccessible protection state; a timestamp is not authorization for arbitrary subvolume operations. Pruning must skip the **whole paired timestamp set** when a required `@data` member is pinned.

State transition: prior accepted parent pinned → pin candidate under lock → send → verify receiver-owned receipt and received UUID → atomically promote accepted candidate → safely release superseded parent. On any failure, including SSH loss, receipt timeout, disk full, crashed sender or inaccessible receiver, preserve last accepted parent; only an explicit recovery protocol can clear an unresolved candidate. Receiver must retain old accepted parent until new one is verified, independent of sender state. Protect against another prune or push between validation and state update.

Proof required: static and unit tests of permission/schema handling, missing state fail-closed, pin lifecycle, prune concurrency, offline receiver; `mango` Playbooks regression; deployment preflight, read-only baseline and receipt check, controlled live incremental from `mars` via direct network, then prune dry-run/controlled real prune showing protected history intact. Keep `btrfs-snapshot-prune.timer` disabled until these gates pass; old Snapper migration and the `pluto` Diaries backup pull are not modified. This file implements no code and changes no timer.
