# 0026 isolated fixture plan and ownership

## Step 1 resources actually used

- Parent Gradle wrapper/JDK 25; tests use the existing Testcontainers-managed Mosquitto `eclipse-mosquitto:2.0.22` with its private container filesystem, mapped ephemeral port and dedicated test publisher/reader credentials. Existing test topics use `diaries/...` safely because the broker is separate from development/production. The test runner owns creation and removal; no existing broker retained messages are touched.
- Browser fixture uses `TestData.readyProjection()` directly, with no broker/DB connection. Its inert MQTT settings reserve `diaries0026baseline` as one valid topic-prefix segment and a distinct client ID; the configured port 18883 is not contacted.
- Reader binds only `127.0.0.1:18082`; temporary static scan server binds only `127.0.0.1:18083`. Generated images live in a unique `images-*` directory under `diaries-web/build/0026-baseline/`. The runner records the exact owned path and deletes that file/directory in its `finally` block. It never mounts or reads NAS content.
- Owner: this Step 1 runner. Stop via its exact `stop` marker, wait for successful exit, verify image-directory removal and ports free. Do not terminate unrelated listeners or recursively remove directories. On interruption before cleanup, inspect `fixture-runtime.txt`, verify the PID belongs to this harness and the resolved image path stays beneath its build directory before cleanup. Retain the evidence/logs.

## Reserved plan for later mixed-type reader checks (not executed in Step 1)

1. Start a **new disposable broker**, independent of ports 1883/9001 and the current Compose services. Prefer ephemeral loopback port mapping; record its exact container ID/image digest and a run label such as `diaries.change=0026`. No production or development retained publications, no host Docker volume, no NAS bind mount.
2. Use namespace `diaries0026fixture` with canonical `diaries/+`, `pages/+`, `fragments/+`, `marquees/+`, `images/+` suffixes. Reader ACL grants read only on those exact five filters after Step 4; a separate fixture publisher has write permission only in the fixture namespace. Test forbidden RPC/date/people/role/synchronization topics. Fixture credentials stay ephemeral and out of captured config/logs. If a controlled responder is needed later, its fixed `diaries` prefix requires a dedicated broker; do not assume responder prefix configurability.
3. Allocate a unique temporary `images-*` directory under `diaries-web/build/0026-fixture/` and serve it on a recorded loopback port. Keep Page scans and `/files/` catalogue paths distinct. Generate all bytes locally. Configure browser-visible public base and Files path using the eventual Step 7 schema, without sending the new property to this strict pre-change reader.
4. Publish synthetic Page-owned MARQUEE/IMAGE rows spanning dates, sequence ties and Pages. Include one Image reused by two IMAGE Fragments, no reference, missing/malformed metadata, missing file, invalid bytes, long/blank/hostile caption/alt, invalid cross-type links and unknown type. Preserve ordinary MARQUEE data matching this baseline for before/after comparison.
5. Test metadata before/after Fragment, update, zero-byte tombstone, reconnect/fresh replay and ACL denial; capture HTTP chronology and browser selection/history/focus on both reader surfaces. No database is needed for retained-reader tests. A later end-to-end responder fixture must use its own disposable database/files and explicit gate control, never the live development database.
6. The later fixture runner owns cleanup in `finally`: close reader/static processes, stop/remove only its recorded broker/container, delete only its generated bytes beneath the verified unique temporary root, and verify ports/container/file absence. Retained fixture topics disappear with that disposable broker; do not issue blanket tombstones against another broker. Preserve results, source/artifact identities and failure logs before cleanup.

Step 1 does not create IMAGE test data, deploy the reader or enable production authoring. It only defines this safe fixture boundary and captures the current MARQUEE comparison point.
